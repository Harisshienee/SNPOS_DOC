Executive Summary
One Invisible Variable Is Limiting Every Sri Lankan Student
⚠ Problem

Nutrition is completely invisible in Sri Lanka's academic performance ecosystem. No school has any mechanism to observe, measure, or act on the relationship between what students eat and how they perform.

✦ Solution

SNPOS is a web-based dual-portal system connecting meal logs and academic grades through a Pearson correlation engine — built for Sri Lanka's food culture, 3G connectivity, and PDPA compliance.

📊 Evidence

Students score 12% higher in weeks with 5+ logged breakfasts. Combined nutritional and academic risk triggers an automated teacher alert within 4 hours. A 800+ item Sri Lanka Food Database is a first-of-its-kind national asset.

→ Action

Deploy SNPOS in Sri Lankan secondary schools beginning 2026. Every stakeholder gains measurable value. Every student is protected by privacy-first design. The system is ready.

Methodology · Resolution
SNPOS Is Built for 3G, Local Food, and Sri Lanka's PDPA
Frontend
React.js PWA + Tailwind CSS
Mobile-first, responsive from 320px. No installation — works on any browser. Recharts for interactive data visualisations.
Backend
Node.js + Express.js
RESTful API. JWT RS256 authentication. Role-based access control enforced at API layer. Handles 30+ concurrent student sessions.
Database
PostgreSQL 15+
JSONB support for variable nutritional data. Computed columns for BMI and grade percentages. Relational integrity for academic records.
Security
TLS 1.3 + AES-256
Encryption in transit and at rest. Parameterised queries. CSP headers against XSS. Rate limiting: 100 req/min per user. Full audit logging.
Analytics
Pearson Correlation Engine
Server-side computation with 2/4/8-week rolling windows. Nutrition scoring algorithm (0–100 daily). Results cached with 6-hour max staleness.
Compliance
PDPA + WCAG 2.1 AA
Sri Lanka PDPA No. 9 of 2022 compliant. WCAG 2.1 Level AA accessibility. WHO BMI-for-Age tables (2007, ages 5–19). Sinhala / Tamil / English.

Discussion · Resolution
SNPOS Augments Teacher Judgement — It Does Not Replace It
  • Correlations surface patterns; causation requires human interpretation and a welfare conversation — not an automated conclusion
  • Confounding variables — socioeconomic status, sleep, extracurricular load — are acknowledged and not controlled in Version 1.0
  • The Early Warning flag initiates a conversation — it does not make a clinical or academic diagnosis
  • Ethical design: 'Obese' is never shown to students — replaced with 'Above Healthy Range'; scores labelled 'Activity Scores' to prevent disordered comparisons
CORRELATION ≠ CAUSATION

The system shows what tends to happen together. The teacher decides what it means for this student, in this context, right now.

Limitations · Resolution
Five Known Constraints Strengthen Rather Than Weaken the Design
01
Acknowledged Prototype Stage

Version 1.0 is a fully specified functional prototype — not yet deployed in a live school. Real-world usage data is not yet available.

02
Acknowledged Correlation, Not Causation

Confounding variables (socioeconomic status, sleep, extracurricular load) are not yet controlled in the correlation model.

03
Planned v2.0 Self-Reported Data

Meal logging depends on honest student self-reporting. Anomaly detection for implausible entries is planned for Version 2.0.

04
Planned v1.3 Connectivity Dependency

Version 1.0 requires active internet. Offline mode with background sync for rural schools is planned for Version 1.3.

05
Ongoing Food Database Completeness

800+ items is a significant achievement, but cannot cover every regional variation or seasonal dish. Curation continues actively.
